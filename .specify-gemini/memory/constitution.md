# DevFlow-Engine 项目章程

## 核心原则

### I. 思考先行 (Think Before Coding)
在编写任何代码之前, 必须明确假设, 识别并呈现多种可能的解释, 并公开权衡利弊. 如果对需求或实现路径存在不确定性, 必须停止并寻求澄清, 而不是盲目猜测.

### II. 简洁至上 (Simplicity First)
坚持编写解决问题的最小代码量. 严禁添加未被要求的"灵活性"或"可配置性". 不为单次使用的代码设计抽象. 如果实现过于复杂, 必须重新评估并简化, 遵循 YAGNI 原则.

### III. 手术刀式变更 (Surgical Changes)
仅触碰实现目标所必需的代码. 严禁在任务范围之外"改进"相邻代码或格式. 必须匹配现有的编码风格. 由本次变更产生的废弃代码(如导入、变量、函数)必须由变更者负责清理.

### IV. 目标驱动执行 (Goal-Driven Execution)
将每个任务转化为可验证的目标. 在实施前定义成功标准, 并通过迭代循环直至验证通过. 每个逻辑变更应遵循"定义目标 -> 编写验证/测试 -> 实施 -> 验证成功"的闭环过程.

## 质量与验证
所有代码变更必须具备相应的验证机制. 无论是新增功能还是修复错误, 必须首先建立失败的验证用例, 然后实施修复, 最后通过验证. 严禁在未经验证的情况下声明任务完成.

## 开发工作流
遵循 研究 -> 策略 -> 执行 的标准生命周期.
1. **研究**: 映射 codebase, 验证假设, 经验性复现问题.
2. **策略**: 基于研究制定切实的实施方案.
3. **执行**: 采用 计划 -> 行动 -> 验证 的微循环处理每个子任务.

## 治理
本章程是项目治理的最高准则, 优先于所有其他非强制性实践. 任何偏离原则的决策必须在 `plan.md` 的"复杂度跟踪"部分中明确记录, 并提供充分的合理化理由.
