# Database Schema

This document describes the PostgreSQL tables created by Flyway migration
`control-plane/devflow-engine/src/main/resources/db/migration/V1__create_core_tables.sql`.

## Migration Policy

- Schema changes are versioned through Flyway under `db/migration`.
- Hibernate DDL auto mode is set to `validate`, so JPA entities must match the
  migrated schema instead of changing tables implicitly at runtime.
- Application tables live in the `devflow_app` schema to keep them separate
  from Temporal tables in the shared PostgreSQL database.
- UUID primary keys are generated by PostgreSQL through `pgcrypto` and
  `gen_random_uuid()`.
- Flexible workflow payloads use `JSONB` to preserve structured agent and
  pipeline context without forcing every generated field into a relational
  column.

## `pipelines`

Stores one end-to-end DevFlow pipeline execution.

| Column | Type | Required | Default | Description |
|--------|------|----------|---------|-------------|
| `id` | `UUID` | Yes | `gen_random_uuid()` | Primary key. |
| `name` | `VARCHAR(255)` | Yes | None | Human-readable pipeline name. |
| `status` | `VARCHAR(32)` | Yes | `PENDING` | Pipeline lifecycle status. |
| `current_stage` | `VARCHAR(128)` | No | None | Name of the currently active stage. |
| `global_context` | `JSONB` | Yes | `{}` | Requirement, repository, and shared execution context. |
| `created_at` | `TIMESTAMPTZ` | Yes | `CURRENT_TIMESTAMP` | Creation timestamp. |
| `updated_at` | `TIMESTAMPTZ` | Yes | `CURRENT_TIMESTAMP` | Last update timestamp. |

Constraints and indexes:

- Primary key: `id`
- Status values: `PENDING`, `RUNNING`, `SUSPENDED`, `COMPLETED`, `FAILED`
- Indexes: `status`, `updated_at`

## `stages`

Stores the stages belonging to a pipeline.

| Column | Type | Required | Default | Description |
|--------|------|----------|---------|-------------|
| `id` | `UUID` | Yes | `gen_random_uuid()` | Primary key. |
| `pipeline_id` | `UUID` | Yes | None | Parent pipeline. |
| `name` | `VARCHAR(128)` | Yes | None | Stage name, such as `REQUIREMENT_ANALYSIS` or `CODE_GENERATION`. |
| `agent_role` | `VARCHAR(128)` | Yes | None | Agent role responsible for this stage. |
| `requires_human_approval` | `BOOLEAN` | Yes | `FALSE` | Whether execution must pause for human approval. |
| `status` | `VARCHAR(32)` | Yes | `PENDING` | Stage lifecycle status. |
| `output_payload` | `JSONB` | Yes | `{}` | Structured output produced by the stage. |
| `created_at` | `TIMESTAMPTZ` | Yes | `CURRENT_TIMESTAMP` | Creation timestamp. |
| `updated_at` | `TIMESTAMPTZ` | Yes | `CURRENT_TIMESTAMP` | Last update timestamp. |

Constraints and indexes:

- Primary key: `id`
- Foreign key: `pipeline_id` references `pipelines(id)` with cascade delete
- Unique key: `(pipeline_id, name)`
- Status values: `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`, `REJECTED`
- Indexes: `pipeline_id`, `status`

## `checkpoint_feedback`

Stores human checkpoint decisions for a stage.

| Column | Type | Required | Default | Description |
|--------|------|----------|---------|-------------|
| `id` | `UUID` | Yes | `gen_random_uuid()` | Primary key. |
| `stage_id` | `UUID` | Yes | None | Stage being approved or rejected. |
| `decision` | `VARCHAR(16)` | Yes | None | Human decision. |
| `feedback_reason` | `TEXT` | No | None | Required when rejecting a stage. |
| `created_at` | `TIMESTAMPTZ` | Yes | `CURRENT_TIMESTAMP` | Feedback timestamp. |

Constraints and indexes:

- Primary key: `id`
- Foreign key: `stage_id` references `stages(id)` with cascade delete
- Decision values: `APPROVE`, `REJECT`
- Reject decisions require `feedback_reason`
- Index: `stage_id`

## Relationships

- One `pipeline` has many `stages`.
- One `stage` has many `checkpoint_feedback` records.
- Deleting a pipeline deletes its stages and their checkpoint feedback records.
